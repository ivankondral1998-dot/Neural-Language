# Neural Language / Neural IR 0.1 — первая отдельная реализация языка для нейронного ядра

Дата: 2026-11-08. Статус: `HOST_TESTED`, `ANDROID_NOT_TESTED`, `RESEARCH_PROTOTYPE`.

**Это не «Искра».** Это новый, отдельно реализованный язык с расширением `.nir`, компилятором в нативный код, типизированным описанием структуры нейросети и встроенным узким помощником оптимизации. Выполняемое приложение — скомпилированная программа на `.nir`, а не Python-скрипт, который интерпретирует команды. Существующие проекты и предыдущие версии не изменены.

## Что есть в версии 0.1

- `brain`, `senses`, `neurons` определяют топологию и создают веса; поддерживаются `relu`, `sigmoid`, `linear`.
- `observe`, `predict` — вход и вычисление выхода.
- `learn ... rate` — **настоящее обновление весов и смещений** через обратное распространение ошибки (SGD, квадратичная ошибка); это не готовая LLM.
- `weight ... add`, `edge ... on/off` — точечное изменение весов и активности связей.
- `tune full|incremental|auto` — полный либо выборочный пересчёт после локальной правки. При новом входе или после обучения кэш недействителен.
- `remember`, `rewind` — снимок и восстановление весов, масок и входа, с сохранением монотонной версии состояния.
- `advise N` — встроенный **не-LLM помощник**: на независимых копиях состояния сравнивает два нативных алгоритма по времени, сверяет выходы, рекомендует `REVIEW_INCREMENTAL` или `NO_CHANGE`. Оригинальные веса не меняет.
- `expect` и `report` — проверка выхода и отчёт JSON. Компилятор дополнительно сохраняет IR JSON с размерами сети, количеством весов, оценкой хранения и диагностикой.

## Как программа превращается в исполняемый код

```text
  programs/*.nir
       │  собственная грамматика
       ▼
  compiler.py (bootstrap compiler: проверка, типы, размеры, ограничения)
       │
       ├── *.nir.json  — Neural IR / модель / команды / рекомендации
       └── *.cpp       — сгенерированный C++17
                 │
                 ▼
        g++/clang++ + native runtime/neural_runtime.hpp
                 │
                 ▼
           бинарный файл x86-64 (на текущей машине)
```

На этапе сборки **используется Python 3** для компилятора и C++17 для нативной среды исполнения. На этапе работы скомпилированной программы Python не нужен. Собственного генератора машинных инструкций и независимости от C++ ещё нет. Оптимизированные алгоритмы пока являются частью родного runtime, а не продуктом нового LLVM-backend.

## Запуск без сети/API

Нужны Python 3 и `g++` (C++17):

```bash
cd NEURAL_LANG_0_1
python3 compiler.py examples/learning.nir -o build/learning --run
python3 compiler.py examples/performance.nir -o build/performance --run
python3 -m unittest discover -s tests -v
```

По умолчанию `report "learning_report.json"` сохраняет файл в рабочем каталоге исполняемой программы (при `--run` — рядом с бинарником). Повторный запуск в той же папке **не перезаписывает** предыдущий отчёт: создаёт суффикс `_1`, `_2` и т. д. Это предотвращает обычное случайное затирание файлов, но не является атомарной защитой от гонки двух одновременно запущенных процессов. Для строгой изоляции используйте отдельные каталоги исполнения.

Имеется режим `--emit-only` для генерации C++ и IR без запуска компилятора:

```bash
python3 compiler.py examples/learning.nir -o build/learning --emit-only
```

## Что доказано на текущей машине

Пример `examples/learning.nir` реализует двухслойную сеть 2→4→1 с ReLU и sigmoid, 500 эпох × 4 обучающих примера логической операции AND. Выходы после обучения:

```text
[0,0] -> 0.0007179911
[0,1] -> 0.0136677955
[1,0] -> 0.01409288996
[1,1] -> 0.9828806816
```

Это 4/4 при пороге 0.5 **на тех же четырёх примерах** — не доказательство обобщения, интеллекта или пригодности для UNO.

`examples/performance.nir`: сеть 128→256→32, 40 960 весов, 2 000 синтетических микроправок; в одной сессии локальный частичный пересчёт выполнялся быстрее полного **простого C++ пересчёта**. Абсолютное ускорение зависит от устройства/системы; с OpenBLAS, Android и современными backend-ами эта версия не сравнивалась.

`tests/test_language.py`: 20 тестов (синтаксис и отклонение ошибок компилятора, нативный запуск, обучение, сохранение/откат, математическая эквивалентность полного и частичного пересчёта для 3 слоёв, проверка помощника). GCC/Clang и один ASan+UBSan запуск: результаты в `verification/`.

## Что не готово

- Нет самостоятельного генератора кода ARM64/Android, NDK/AAB/APK, UI, доступа к Android SDK. Ядро потенциально переносимо как C++17, но на Android **не проверено**.
- Нет типизированного произвольного графа, attention, свёрток, многопоточности, GPU/NPU, F16/INT8, структурно-разреженного хранения или промышленной оптимизации кода.
- Веса пока `double`, то есть FP64; включение/выключение связей не сжимает память. Специализированная оптимизация касается локального пересчёта после изменений, а не компрессии модели.
- `advise` — **ограниченный измеряющий помощник**, а не автономная нейросеть, не LLM, не автор нового алгоритма и не система самостоятельно модифицирующая доверенный компилятор.
- Нет тестов на неизвестных задачах, длительной адаптации и сохранении навыков. Нет научных оснований считать эту версию универсально быстрее и умнее существующих систем.
- Отчёты получают уникальные имена при совпадении; защита от конкурентной записи и изоляция произвольных процессов ОС не реализованы.

## Следующее обоснованное направление

После проверки языка на простом ядре — расширить Neural IR для матриц/тензоров и порционных обновлений, внедрить независимую проверку на фиксированных данных и затем сравнить с C++/BLAS на равных условиях. **Не переносить на UNO без отдельного решения владельца.**

Исходный нормативный черновик NS002 сохранён в `references/` для отслеживания происхождения идей, но новая реализация не заявляет соответствия всем пунктам того черновика.


## INT8 and resource budget — review1 correction (2026-11-08)

`neurons ... int8` now owns **only** a packed-byte weight array (`q`). The alternative FP64 array (`w`) is empty. However, the separate one-byte-per-edge `enabled` mask, FP64 biases and FP64 activations remain. Therefore only the **weight array** has an 8× byte reduction, not total RAM. There is no native ARM64/INT8 kernel yet.

`budget BYTES MACS` rejects programs when the **estimated static numeric tensor bytes** exceed BYTES or the full forward-pass MACs exceed MACS. The byte estimate includes weights, gate masks, biases, input, preactivation and activation caches. It excludes heap allocator overhead, checkpoints, advisor clones, temporary gradients and pending deltas: **not a hard process RSS limit**. See `../review/REVIEW_RU.md`.
