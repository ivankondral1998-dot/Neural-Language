# Контракт Neural Language 0.3 — интеграционный прототип

## Новый путь выполнения

Две программы `.nir`: `integrated.nir` (обучает и сохраняет модель) и `inference.nir` (загружает и прогнозирует). Оба исходника компилируются в native C++17 через bootstrap Python-компилятор. Это не self-hosted compiler.

### `validate [inputs] target [outputs] tolerance T`

Оценка всех выходов на копии состояния; для PASS каждая абсолютная ошибка должна быть ≤ T. Ошибка завершает native-программу ненулевым кодом. Не изменяет веса, маски, текущий ввод, версию, режим, кэш, счётчики исходной модели; пишет журнал успешной проверки. Это не доказательство независимости тестовых примеров — их подбирает автор программы.

### `optimize N`

Встроенный помощник сравнивает `AUTO` и `FULL` на одиночных изменениях весов крупнейшего слоя. Три повторения, в разном порядке, с проверкой каждого выходного значения. При повторяемом выигрыше AUTO (по определённому порогу) применяет `AUTO`; иначе `FULL`. Веса не меняет. Применение разрешено самим наличием команды в исходнике `.nir`. Команда не модифицирует `.nir` и не генерирует новые алгоритмы. Синтетический профиль НЕ представляет все реальные нагрузки.

### `save_model "X.nlw"` / `load_model "X.nlw"`

Формат `NLMODEL2`: название формата, число входов, число слоёв, выбранный режим, затем для каждого слоя его имя и параметры, смещения, эффективные веса в FP64-представлении и бинарные маски. INT8-веса сериализуются по квантованным значениям и восстанавливаются с проверкой точности. Сеть для загрузки должна иметь идентичные формы, имена, типы активаций и хранения. Содержимое считывается в копии, живые веса меняются только после полной проверки. Увеличивается версия, кэш сбрасывается. Снимки, динамические следы обучения и метаданные экспериментов не входят в этот формат.

Файл сохраняется в текущей рабочей папке и не должен перезаписать существующий. Программа выбирает свободное имя с суффиксом. Гарантий атомарной/конкурентной безопасности файловой системы нет; `.nlw` нельзя считать безопасным для загрузки из недоверенных источников.

### Технические ограничения

`budget` — только статическая оценка основных тензоров и MAC одного полного прохода, не hard real-time и не предел RAM. INT8-обучение по прежнему теряет малые шаги; в этом конкретном потоке используется FP64, чтобы не выдавать экспериментальное INT8 за готовую технологию. Встроенный выбор оптимизации основан на фиксированной синтетической нагрузке, не имеет независимого производственного бенчмарка. Уникальные свойства языка относительно C++ ещё не доказаны. Нет тестов ARM64/Android.
