# Neural Language 0.4 — направленный ациклический нейронный граф (DAG)

**Статус:** интеграционный прототип, Linux x86-64 / C++17, независимый эксперимент Neural Language. UNO не затронут. Никаких утверждений об ускорении, самообучающемся агенте или Android.

## Что изменено

Расширено объявление `neurons` внутри `brain`:

```nir
brain BranchingDemo {
    senses 2
    neurons left 2 linear from input
    neurons right 2 linear from input
    neurons combined 1 linear from left right
    init 17
}
```

Родители слоя перечисляются после `from`. Входные векторы родителей **конкатенируются в указанном порядке**: в примере у `combined` 4 входных компонента (`2` от `left` + `2` от `right`). Разрешены `input` и только **уже объявленные** слои. Граф автоматически ацикличен благодаря топологическому порядку. Дублирование родителя, неизвестный/будущий родитель, неиспользуемая ветвь и превышение лимитов — ошибки компиляции. Результат программы всегда равен выходу последнего объявленного слоя. Старая форма `neurons name N ACT [int8]` сохраняет прежнюю последовательную семантику.

Прямой проход выполняет независимый нативный расчёт каждого слоя; обратный проход аккумулирует вклад **каждого потомка** в градиент общего предка. Градиенты всех весов рассчитываются до их изменения. Маски отключённых связей учитываются в прямом и обратном проходах. Стандартные `observe`, `learn`, `predict`, `validate`, `remember`, `rewind`, `weight`, `edge`, `save_model`, `load_model` поддерживаются для DAG.

Граф **статичен после компиляции**: команды изменения топологии во время исполнения пока нет. Это не полноценное произвольное машинное вычислительное представление (нет тензорных форм/attention/циклов в графе). Размерный контракт `budget` остаётся лишь статической оценкой; временные конкатенации и градиенты не входят в неё.

## Преднамеренные ограничения оптимизации

В ветвящемся графе **всегда производится полный пересчёт**. Прежняя инкрементальная оптимизация для последовательной сети не переносится без математического и регрессионного доказательства. Команды `tune incremental`, `advise`, `verify`, `optimize` для DAG отклоняются на этапе компиляции, а `AUTO` фактически использует полный пересчёт. Это предотвращает ложные результаты проверки двух «разных» вычислительных путей, когда оба работают одинаково.

## Сериализация

`NLMODEL3` сохраняет граф вместе с индексами родителей, порядком, весами, смещениями, масками и режимом вычислений. Загрузка проверяет топологию **до** изменения текущей модели. Предыдущий `NLMODEL2` оставлен неизменным для последовательных сетей версии 0.3. Это локальный формат для доверенных файлов, не безопасный загрузчик произвольных данных.

## Воспроизводимая проверка

```bash
bash run_graph.sh
cd language
python3 -m unittest tests.test_graph -v
```

Два `.nir`-файла — `examples/graph_train.nir`, `examples/graph_inference.nir`. Обучение на четырёх заданных точках, оценка двух отдельных точек, запись и восстановление весов в отдельном бинарном процессе. `oracle_graph.py` независимо от C++ парсит сохранённые веса и пересчитывает контрольные ответы. Файл `tests/graph_gradient_oracle.cpp` независимо считает численные градиенты конечными разностями и сравнивает со значениями обучения на графе с общим предком и двумя ветвями. Это проверка математических операций на выбранных примерах, но **не** доказательство корректности произвольного DAG/INT8-обучения.

## Критерии этапа / границы

- Подтверждены: ветвление, объединение, топологическая проверка, базовое обучение, восстановление графовых весов, совместимость последовательного `.nir` на отдельных проверках.
- Не подтверждены: произвольная динамическая перестройка графа, обучение большой модели, производительность ARM64/Android, реальное принудительное ограничение RAM, ускорение разреженного DAG, устойчивость обучения INT8, доступ к GPU/NPU, самоизменение компилятора/помощника.
