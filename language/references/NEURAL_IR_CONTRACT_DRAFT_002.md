# Neural IR: черновой контракт семантики — НЕ реализация

Этот документ фиксирует требования, которые выявлены экспериментами NEURAL-STATE-001/002, но не утверждает дизайн или пригодность для UNO.

1. **StateRead(version):** у каждого входа, веса и структурной маски имеется версия. Вычисленный кэш допустим только для соответствующего набора версий.
2. **ChangeSet:** пакет изменений может содержать `SetInput`, `DeltaWeight`, `DeltaEdgeWeight`, `ToggleEdge`. Все индексы и размеры проверяются *до* применения; ошибочный пакет не изменяет состояние.
3. **DependentNodes(ChangeSet):** зависимость распространяется от изменённых весов к предактивациям, затем к нелинейным активациям и выходам; изменения второй матрицы/маски имеют прямую зависимость от текущих активаций.
4. **Activation semantics:** ReLU вычисляется из сохранённой предактивации `z`, а не только из `a = max(0,z)`; иначе невозможно в общем случае корректно обработать переход через 0.
5. **Strategy(Full|Incremental):** runtime выбирает стратегию с возможностью полного пересчёта при изменении входа, недостоверном кэше, чрезмерной плотности изменений и слишком большой ошибке численного состояния. Выбор стратегии не меняет контракт вычисления выхода.
6. **Correctness:** для одинакового начального состояния и допустимого ChangeSet полное и частичное исполнение должны давать эквивалентные состояния при установленном численном допуске. Для критических применений нужны более сильные численные гарантии и откат.
7. **Authority separation:** никакое состояние сети, самообучение или текстовое свидетельство не создаёт полномочий на операции с устройством или защитными механизмами. Предполагаемые права исполнения задаются независимым контуром.

**Открытые проблемы:** обучение и изменение топологии по правилам оптимизатора; долгосрочный численный дрейф; компиляция произвольного графа; планирование памяти; сбор телеметрии на ARM64; проверка переносимости оптимизации; сравнение с промышленными backend-ами.
