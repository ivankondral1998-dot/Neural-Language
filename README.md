# Neural Language

> **Перед разработкой прочитать [NEURAL_LANGUAGE_PRODUCT_CHARTER.md](NEURAL_LANGUAGE_PRODUCT_CHARTER.md) и [AGENTS.md](AGENTS.md).** Утверждённая цель — полноценный специализированный язык .nir с проверяемыми преимуществами на телефонах. Отдельные помощники, компактные модели и JNI — необязательная инфраструктура или исследовательские компоненты; они не заменяют продукт. Пока мобильное превосходство не доказано.

Исследовательский **специализированный язык для разработки, обучения, проверки и оптимизации нейронных систем**. Цель владельца — **новый язык программирования**, способный описывать, компилировать и исполнять нейронные программы, с исследованием реальных преимуществ на мобильных устройствах. Встроенные или внешние помощники остаются необязательными инструментами.

**Статус: 0.3 Integrated / HOST-TESTED / CONDITIONAL.** Это не UNO и не готовая промышленная платформа ИИ. Работа на Android, преимущество над промышленными реализациями и самостоятельное улучшение исходного кода помощником **не доказаны**.

## Состав репозитория

- `language/compiler.py` — компилятор формата `.nir` в Neural IR JSON и C++17.
- `language/runtime/neural_runtime.hpp` — нативное вычислительное ядро и ограниченный помощник выбора режима вычислений.
- `language/examples/` — примеры на нашем языке. `integrated.nir` обучает и сохраняет модель, `inference.nir` загружает и выполняет предсказание без обучения.
- `language/tests/` — автоматические проверки компилятора, численной корректности и сохранения моделей.
- `oracle_integration.py` — независимый расчёт для узкой линейной демонстрации.
- `docs/RELEASE_0_3_README_RU.md` и `docs/RELEASE_0_3_FINAL_STATUS_RU.md` — подробности, ограничения и исторические результаты.
- `AGENTS.md` и `language/AGENTS.md` — обязательные инструкции для разработчиков и ИИ-агентов.

## Быстрый запуск

Требуется **Linux, Python 3 и GCC/Clang с C++17**. BLAS необязателен.

```bash
bash run.sh
```

Скрипт создаёт отдельную `runs/run_XXXXXX` и выполняет полный цикл: компиляция, обучение, сохранение весов, загрузка в другую программу и проверка предсказаний. Для Clang: `CXX=clang++ bash run.sh`.

```bash
cd language
python3 -m unittest -q tests.test_integration
python3 -m unittest -q tests.test_language
python3 -m unittest -q tests.test_quantization_fixes tests.test_verifier
python3 -m unittest -q tests.test_hardening
```

## Точная граница возможностей

Текущий путь: **`.nir` → Neural IR → C++17 → GCC/Clang → нативный бинарник**. Python нужен для компилятора, C++ — для вычислений. Помощник пока только сравнивает заранее заданные режимы на ограниченной нагрузке: он **не переписывает код и не является автономным исследователем**.

`budget` даёт статическую оценку, а не абсолютную гарантию RAM/времени. INT8-обучение и безопасность загрузки недоверенных моделей требуют дальнейшей работы. Никаких заявлений о превосходстве над C++ или OpenBLAS без честных независимых измерений.

## Эксперимент NL-COMP-002: точечные изменения входа (.nir)

В изолированной ветке `feature/change-aware-input-20261108` реализована инструкция `observe_delta INDEX add AMOUNT` в самом языке, её компиляторная проверка `NeuralChanges/1` (только последовательный dense-граф) и нативная обработка пакетов обновлённых входных значений. Сохранены исходники, тесты, отложенные GCC/Clang OpenBLAS-измерения и отрицательные случаи: [research/change_aware_input_002/RESULT_002_RU.md](research/change_aware_input_002/RESULT_002_RU.md).

На Linux x86-64 и двух компиляторах: 8 из 16 отложенных сценариев дали медианное ускорение более 20% против полного OpenBLAS, без медианной регрессии более 20% в остальных. Это **не подтверждённое преимущество на телефоне**; Android/ARM64, общий DAG, объединение NeuralShapes/NeuralEffects и сравнение с другими мобильными backend остаются открытыми. Главная цель остаётся изложена в [NEURAL_LANGUAGE_PRODUCT_CHARTER.md](NEURAL_LANGUAGE_PRODUCT_CHARTER.md).

## Этап NL-COMP-004 — единые эффекты и входные изменения

В [docs/NEURAL_EFFECTS_CHANGES_INTEGRATION_20261108_RU.md](docs/NEURAL_EFFECTS_CHANGES_INTEGRATION_20261108_RU.md) описана проверенная интеграция `NeuralEffects/1` с `NeuralChanges/1` в компиляторе. Исправлен ошибочный отказ на `observe_delta` после `rewind` снимка с сохранённым входом; статически проверяются жизненный цикл снимков и предусловия входа. Синтаксис старых программ и их сгенерированный C++ сохранены. 73 теста PASS по отдельным группам, сквозной цикл PASS; общий монолитный прогон прерывался по лимиту времени. `main`, DAG, Android и общий `NeuralShapes` не затронуты.

## NL-COMP-005 — согласование формы, эффектов и нейронных изменений

Изолированная ветка `feature/typed-changes-effects-20261108` интегрирует проверку `NeuralShapes/1` с уже действующими `NeuralEffects/1` и `NeuralChanges/1`. `observe_delta` имеет типизированные индекс и числовое изменение; повреждённые формы, бюджеты, операнды и метаданные IR отвергаются **до** нативной генерации. Полный отчёт: [docs/NEURAL_SHAPES_EFFECTS_CHANGES_20261108_RU.md](docs/NEURAL_SHAPES_EFFECTS_CHANGES_20261108_RU.md). 12 новых тестов и 73 завершённых старых теста PASS отдельными группами; девять исходных C++-выходов побайтно сохранены. Это всё ещё последовательный dense-язык: DAG и Android/ARM64 не проверены.

Для повторения из корня: `cd language && python3 -m unittest -q tests.test_shapes_changes_integration`; для сквозного прогона: `bash run.sh` из корня.

## NL-COMP-006 — DAG и выборочное обновление нейронных состояний

Экспериментальная ветка `feature/dag-change-aware-20261109` объединяет графовые зависимости (`neurons ... from ...`) с существующими `NeuralShapes/1`, `NeuralEffects/1`, `NeuralChanges/1` и нативным выборочным пересчётом изменённого входа. [Точный отчёт, тесты, отрицательные случаи и сравнение с OpenBLAS](docs/NL_COMP_006_DAG_CHANGES_RU.md). Старые последовательные программы сохраняют исходный C++; графовый формат модели — `NLMODEL3` и пока не совместим с мобильным пакером. Это результат Linux x86-64, **не доказанное преимущество Android**; main не меняется.
