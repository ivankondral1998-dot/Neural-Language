### E01. LayerNorm после исправления 006 остаётся численно ненадёжным

Источник: `006/numeric_corrections.py:55–76`, `006/NL_MATH_006_AUDIT_RU.md`, §3.1.

| Расчёт | Результат |
|---|---|
| `layernorm_stable` из 006 | `(-1.4142135623729801, 0.0)` |
| Независимый расчёт с Decimal, 120 цифр, над точными входными FP64-значениями | `(-0.9999999999999255, 0.9999999999999255)` |

Для oracle считать среднее и дисперсию над точно декодированными числами с контролируемой высокой точностью; для backend отдельно доказать точность выбранного центрирования/масштабирования. Одного переименования в stable недостаточно.

### E14. Идентичность байтов не завершает идентичность исполняемой модели

### 4.2 LayerNorm и cross-entropy

Для n>0, epsilon>0 и конечных вещественных данных:

`μ=(1/n)Σx_i`, `v=(1/n)Σ(x_i−μ)^2`,

`LN_i=γ_i(x_i−μ)/sqrt(v+epsilon)+β_i`.

Условие gamma=1,beta=0 даёт `Σ LN_i=0` в R. Для двух чисел a,b: среднее отклонение по модулю `d=|b−a|/2`, нормированные значения `±d/sqrt(d²+epsilon)`. Это независимый эталон E01. Точное масштабное тождество 006 верно; его FP64-вычисление без error analysis не является доказанно устойчивым алгоритмом.

Для CE выбрать один `k=min argmax z`, `m=z_k`, `r=Σ_{j≠k} exp(z_j−m)`:

`CE(z,t)=(m−z_t)+log1p(r)`.

Равенство стандартной CE доказывается вынесением exp(m). Все аргументы exp неположительны. Если промежуточная разность конечных logits становится −Inf в FP64, это внутреннее underflow-приближение требует профиля; входные NaN/Inf разрешёнными от этого не становятся. Финальная ошибка и правильность градиента — отдельные обязательства.

### 4.3 Attention и его численный контракт

Для непустого набора допустимых ключей A, конечных real scores и value:

`p_j=exp(s_j−m)/Σ_{k∈A}exp(s_k−m)`, `o=Σ_{j∈A}p_j v_j`, `m=max_A s`.

Каждая координата o лежит между минимумом и максимумом соответствующих v_j: p_j≥0 и Σp_j=1. Поэтому E02 не имеет непредставимого математического результата.

Инвариант online-softmax после набора J:

`d_J=Σ_{j∈J}exp(s_j−m_J)`, `u_J=Σ_{j∈J}exp(s_j−m_J)v_j`.

При новом максимуме умножение старых d,u на `exp(m_old−m_new)` сохраняет эти суммы; добавление нового слагаемого завершает индукцию. Это доказательство в R. На машине необходимы защищённые score и weighted reductions, политика underflow/overflow и error budget. Online numerator может переполниться даже при конечном u/d — реальное равенство этого не предотвращает.

### 4.4 Корректная композиция ошибок DAG

Пусть x — tuple точных родительских значений, x̂ — приближённых, `e_in=||x̂−x||` в **заданной product-норме**. Пусть f — точный оператор, f̃ — его математическое приближение, а машинная реализация даёт дополнительную ошибку ρ.

Версия A:

`||ŷ−f(x)|| ≤ Lip(f̃;Ω) e_in + ||f̃(x)−f(x)|| + ρ`.

Версия B:

`||ŷ−f(x)|| ≤ Lip(f;Ω) e_in + sup_{u∈Ω}||f̃(u)−f(u)|| + ρ`.

Доказательство: добавить и вычесть соответственно f̃(x) или f(x̂), затем применить треугольное неравенство. Ω должна покрывать нужные входы. В max-product норме для concat L=1, для сложения двух аргументов L=2; число использований нельзя терять. Для линейного приближения:

`e_out ≤ ||Ŵ||∞ e_in + ||Ŵ−W||∞ ||x||∞ + ||b̂−b||∞ + ρ`.

У активаций linear/ReLU/tanh L≤1, sigmoid L≤1/4 в R. Для normalization L зависит от epsilon и gamma; attention требует ограничений на аргументы. При неизвестном локальном bound результат **NO_BOUND**, а не нулевая ошибка. При вычислении самого bound в float нужны наружное округление/интервалы: заниженный округлением сертификат не является строгим.

Для fixed input квантования: `Wx−Ŵx̂=(W−Ŵ)x+Ŵ(x−x̂)`. Неравенства 004/005 следуют из него. `|w−ŵ|≤s/2` только при nearest-round и отсутствии clipping в точной модели; saturation и machine rounding учитываются отдельно.

### 4.5 FULL/STRICT и кэш

Теорема остаётся условно верной для конечного DAG: одинаковые корректные входы, фиксированная machine semantics каждого узла, sound dependency tracking, канонический кэш, immutable read-state в течение операции. Незатронутый узел сохраняет прежний machine-result; затронутый пересчитывается точно тем же алгоритмом. Индукция по топологическому порядку даёт равенство выходов.

Нужно отдельно включить **отказы** и допустимые эффекты. Если floating-point flags/traps наблюдаемы, пропуск вычисления может изменить их; профиль должен либо исключать их из Obs, либо сохранять. Численное `+0==-0` безопасно только для объявленного legacy-набора наблюдений/операторов. Его нельзя без доказательства распространять на будущий reciprocal/signbit/copysign или битовую сериализацию.

Это доказательство не требует оценивать накопленный drift: канонический пересчёт устраняет сам альтернативный порядок в затронутых строках. Он не доказывает ускорение и не равен доказательству корректности реализации dependency tracking.

### 4.6 Обучение и границы ошибки

Для дифференцируемой вещественной композиции правила MSE, матричного AD, суммирования всех downstream contributions и градиентов A,B LoRA корректны. Для shared-параметра θ сумма идёт по **всем его использованиям**, а update выполняется один раз. ReLU(0) имеет выбранный субградиент; STE — отдельный surrogate, не точная производная quantize.

Для plain SGD при одном и том же шаге η, данных и Lg-Lipschitz градиенте на области обеих траекторий:

`e_{t+1} ≤ (1+η Lg)e_t + η δg_t + ρupdate_t`.

Доказательство — треугольное неравенство для двух обновлений. Это условная конечногоризонтная оценка, не теорема сходимости и не полезности модели. Для optimizer со state оценивать расширенный state. Для discrete quantization малое изменение около порога может изменить код на целый шаг: универсальная малая Lipschitz-граница не следует. Каноническое детерминированное повторение при идентичном полном snapshot — другой вид гарантии.

**Неверно говорить «никакая строгая граница невозможна».** Возможны ограничения домена, интервальные bounds, более широкая арифметика, отказ при невозможности сертификации и точный machine-reference. Не доказана общая *малая и полезная* ошибка для всех поддерживаемых/будущих сетей и произвольного горизонта обучения. Даже нулевая machine-разница не доказывает accuracy на новых данных.

### 4.7 Помощник, предложение и публикация

Минимальная математическая запись нейронного помощника:

`h_i^{φ_i}: X_i → Proposal_i ∪ {ABSTAIN}`,

`X_i=Encode_i(Task,ReadOnlySnapshot,AllowedEvidence)`.

Нужно зафиксировать Encode_i и декодирование результата. Если Encode_i отождествляет два состояния, требующих разных решений, детерминированный h_i не сможет различить их; надо расширить вход либо сузить задачу/разрешить ABSTAIN. Это проверяемое необходимое условие, не требование передавать каждому помощнику все веса.

`V(Task,Base,Candidate,Evidence)` — независимая детерминированная проверка с soundness только относительно явно названного свойства. Для типизации возможна полная проверка ограниченного языка; для качества на распределении конечная validation battery даёт лишь эмпирическое свидетельство.

`Commit` допустим только если совпадают Task/base/candidate/evidence bindings, проверены allowed mutations и полное состояние, ν в допустимом диапазоне, verifier успешен и сравнение current base с публикацией линейризовано. Helper не имеет прямой или косвенной возможности мутации published state.

Тогда no-write, reject-preserves-state и stale rejection доказываются по переходам автомата. Ни одна из этих теорем не доказывает, что φ_i полезны, независимы по ошибкам или оптимально выбраны. Долговечность хранения — отдельная теорема с предпосылками FS и recovery, пока не доказанная здесь.

### 4.8 Недостающие явные правила AD для будущих операторов

Ниже — математические дополнения для проверки, не новые операторы действующего языка. При `p=softmax(s)`:

`J_softmax=diag(p)−ppᵀ`, `||J||∞=max_i 2p_i(1−p_i)≤1/2`.

Это следует из производной отношения экспонент; сумма модулей строки равна двум диагональным слагаемым. Для фиксированной маски производные по исключённым scores равны нулю; all-masked остаётся вне домена.

Для LN положим `u=x−μ1`, `r=sqrt(||u||²/n+epsilon)`, `P=I−11ᵀ/n`. Тогда

`J_LN=diag(gamma)(P/r−uuᵀ/(n r³))`.

В евклидовой норме `||J_LN||₂≤||gamma||∞/sqrt(epsilon)`. На подпространстве, ортогональном 1 и u, собственное значение внутреннего оператора 1/r; вдоль u — epsilon/r³; вдоль 1 — 0. Значит максимум не превосходит 1/r. Это показывает, почему epsilon>0 — существенное условие и почему нельзя без доказательства положить L_LN=1. Не смешивать эту 2-норму с ∞-нормой DAG без коэффициентов перехода.

Для `O=PV`, `P=softmax_rows(S)`, `S=QKᵀ/sqrt(d)` и upstream G:

`dV=PᵀG`, `dP=GVᵀ`,

`dS=P⊙(dP−row_sum(P⊙dP))`,

`dQ=dS K/sqrt(d)`, `dK=dSᵀ Q/sqrt(d)`.

Формулы следуют из matmul-AD и Jacobian softmax. Маска фиксирована, градиент не переносится через запрещённые пары. Для embedding/gather с повторными индексами backward — scatter-**add**, а не overwrite. При tied embedding/output их contributions складываются в один параметр.

Скрипт `check_derivatives.py` независимо сравнил все компоненты matmul A/B, LN x, causal attention Q/K/V на малых гладких входах с центральными разностями при h=1e-4,1e-5,1e-6. Предварительно задан допуск 1e-7; максимальная наблюдённая абсолютная невязка `2.029725498786661e-9`. Это ограниченная численная проверка формул, не свидетельство существования native AD и не испытание устойчивости на E01/E02.

## 8. Вердикт о готовности и приоритеты

| Этап | Что остаётся пригодным | Что мешает принять весь этап безусловно |
|---|---|---|
| 001 | Dense/DAG real-формулы, канонический partial proof | E05, ограниченный oracle и условные backend-предпосылки |
| 002 | Matmul/LoRA A,B, online identity, арифметика ресурсов | Старые numeric-дефекты, E06/E07; историческая трактовка helper ресурсов |
| 003 | Отдельные φ_i, read-only proposals, k=0 | Неполная схема и neural task contract; E13/E15; bitwise формулировку заменяет уточнение 005 |
| 004 | Dtype/storage/train-policy разделение, условные H1–H3 | Требует поправок 005 и конкретных operator/state схем |
| 005 | Canon G1, уточнённые G2/G3, различие профилей | E08–E12/E14; это спецификационные обязательства, не готовая реализация |
| 006 | Четыре прежних дефекта воспроизводимы, dot-float раздельные профили | Новые E01–E04, сохранённые E05/E06, несовпадение ID E15 |

**Сохранить:** разделение real/machine semantics; канонический пересчёт как строгий путь; явные численные профили; typed weights отдельно от storage и train-policy; обязательное суммирование всех use-gradients; immutable proposals, отдельный verifier и k=0.

**Не принимать как готовое:** universal corrected oracle 006, общий tensor/dtype/AD контракт без реестра, перенос strict гарантий на main, перенос LoRA-resource модели на отдельных помощников, общий crash-durable commit, любые заявления о полезности помощников или победе на телефоне из одних формул.

Три первых технических изменения после решения владельца:

1. **Сделать надёжным независимый численный эталон выбранного профиля.** Закрыть E01–E06, явно определить входные типы, отказ и допуски; включить новые контрпримеры в регрессии. Без этого проверяющий может сам закреплять ошибку.
2. **Зафиксировать минимальный поддерживаемый operator/type/state контракт и сверять его с одной выбранной веткой.** Определить области, формы, casts, reduction, aliases, градиенты и гранулярность update; доказать/проверить соответствие .nir→IR→native для этого подмножества. Не требуется одновременно реализовывать все dtype и все сети.
3. **Определить один конкретный класс нейронного помощника до масштабирования системы.** Вход, собственные φ, допустимый результат, objective, ABSTAIN, независимый verifier и стоимость относительно NO_HELPER. Пока это не определено, реализация общего координатора не доказывает развитие нейронных возможностей языка.

**Готовность по частям:** условные математические леммы пригодны как основа ограниченной реализации; текущий полный универсальный контракт — нет; архитектура помощников — пригодна как рамка полномочий, но недостаточна как спецификация обучаемой системы. Отдельное разрешение на реализацию этим аудитом не подразумевается.

## 9. Научные источники для проверки известных формул

Основные выводы этого отчёта получены из собственных расчётов и исходников, а не из авторитета публикаций. Проверены первичные источники:

- Blanchard, D. Higham, N. Higham, *Accurate Computation of the Log-Sum-Exp and Softmax Functions*, [arXiv:1909.03469](https://arxiv.org/abs/1909.03469): математически равные формы имеют разное FP-поведение; shift сам по себе не даёт универсальной гарантии.
- Ba, Kiros, Hinton, *Layer Normalization*, [arXiv:1607.06450](https://arxiv.org/abs/1607.06450): определение LN, не сертификат конкретного алгоритма 006.
- Hu et al., *LoRA*, [arXiv:2106.09685](https://arxiv.org/abs/2106.09685): низкоранговые обучаемые матрицы при фиксированной базе; не обязательная архитектура помощников Neural Language.
- Dao et al., *FlashAttention*, [arXiv:2205.14135](https://arxiv.org/abs/2205.14135): известный IO-aware attention; его GPU-результаты не переносятся на A52 или данный Python-эталон.

Эти известные формулы не следует объявлять открытием Neural Language. Возможный вклад языка — в проверяемом выражении, компиляции и эффективном исполнении полезных программ; математическая корректность необходима, но сама по себе не доказывает практического преимущества.
