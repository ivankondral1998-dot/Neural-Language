# Neural Language — математические контракты

Статус: исследовательская спецификация ограниченного подмножества; общая готовность не установлена. Дата 2026-11-11. Версии кода и проверенные расхождения — в NL-MATH-CODE-COMPLIANCE.md. Этот документ определяет предлагаемую семантику, она не меняет существующие ветки.

## 1. Типы и состояния

Регистр R описывает каждый поддерживаемый тип: множество допустимых битовых слов, декодирование в значение, допустимые операции, округление, обработку исключений. Вес `T=(id,shape,dtype,logical_bits,qspec,train_policy)`. Физический layout и кодировка задаются отдельно; кодировщик и декодировщик обязаны сохранять логическое значение в заявленном профиле. Общие типы допустимы только после регистрации их правил; неподдерживаемое сочетание отвергается до выполнения. Для связанных весов graph содержит общий id, а не только равные байты. Машинный профиль фиксирует аккумулятор, порядок операций, FMA, среду округления, subnormal/FTZ, backend и libm, обработку NaN, infinity и signed zero.

Состояние `S=(G,Θ,M,O,RNG,cursor,input,cache,version,profile)`. Сохраняемый снимок включает все данные, влияющие на будущую траекторию: граф, параметрические идентичности, весовые биты, маски, оптимизатор, master, RNG, scheduler, sampler, cursor и связанные версии, если они присутствуют. Runtime-кэш включает состояние вычисления и ключ зависимостей. Состояние текущей сессии не обязано быть опубликованной ревизией. Правила ошибок определяют, какие эффекты наблюдаемы и какой завершённый префикс сохраняется. Публикация отдельного SGD-шага не означает атомарности всей команды обучения.

Для конечного ациклического графа `h_v=concat(a_p)` в объявленном порядке, `z_v=b_v+(M_v⊙W_v)h_v`, `a_v=φ_v(z_v)` — вещественная семантика. Графы с циклами, stateful операторы, внимание, общие тензорные ранги и преобразования формы требуют отдельного зарегистрированного контракта. Предлагаемая модель расширяема, но не является доказательством поддержки произвольной сети.

## 2. FP64 и инкрементальность

Вещественное `Σ w_i x_i+b` не задаёт поведение binary64. Скалярная машинная строка задаётся `t_0=b; t_{i+1}=fl(t_i+fl(w_i*x_i))` в фиксированном порядке без FMA. Для BLAS задаётся отдельный backend-алгоритм, который может отличаться. Результатом операции является значение или определённый отказ; запрещённый ввод проверяется до оптимизаций. Observable включает выбранные эффекты и ошибки, а не только выход.

Теорема для конечного DAG: если предшествующий кэш каноничен для той же версии состояния и backend, все зависимости учитывают биты каждого значимого аргумента, затронутые операторы выполняются тем же детерминированным машинным алгоритмом и в том же порядке, а незатронутые входы и параметры битово равны, то выборочный результат равен FULL по битам. Доказательство — индукция по топологическому порядку. Для полностью ненаблюдаемых диагностических FP flags их исключение задаётся явно; при наблюдаемых флагах надо также воспроизводить их эффекты. При исключении до публикации частичный кэш недействителен. Изменение backend, маски, layout, графа или неизвестная зависимость требует безопасного пересчёта либо отказа.

IEEE равенство `+0==-0` само по себе не даёт побитовой эквивалентности. Например `signbit(-0)=1`, `signbit(+0)=0`; сравнение по численному значению допустимо лишь для операторов и наблюдений, где знак не различим. ReLU в точке 0 имеет математический субдифференциал [0,1], для обучения реализующий профиль отдельно фиксирует выбранное значение, например 0.

Наивное `z'=fl(z+WΔx)` в общем случае не совпадает с FULL. При w=(9e8,1,-9e8), x=(9e8,0,9e8), x'=(9e8,1,9e8) FULL=0, а добавление delta даёт 1. Поэтому для произвольных допустимых входов и сокращённого накопления без достаточной дополнительной информации строгой эквивалентности нет. Это не запрет существования других точных алгоритмов и не запрет условных оценок ошибок.

## 3. Квантование и ошибки

Пусть q=clamp(R(w/s)+z,qmin,qmax), ŵ=s(q-z), s>0. R, scale, zero-point, ось, границы и порядок машинных операций — части типа. Для nearest и отсутствия clipping в точной арифметике `|w-ŵ|≤s/2`. При clipping эта оценка не действует. Для любого x в R: `|(W-Ŵ)x|≤Σ|W_j-Ŵ_j||x_j|` и `Wx-Ŵx̂=(W-Ŵ)x+Ŵ(x-x̂)`.

Для целочисленного dot достаточно `|bias|+Σ |qw-zw||qx-zx|≤2^(a-1)-1` для signed a-bit аккумулятора, при условии точного вычитания и умножения в достаточно широких типах. Саму проверку выполнять широкими целыми до вычисления. Это достаточное, не необходимое условие.

Для узла f, приближения f̃, reference x и approximation x̂: `||ŷ-f(x)||≤L(f̃,Ω)||x̂-x||+||f̃(x)-f(x)||+ρ`, если оба входа лежат в Ω и f̃ Lipschitz на Ω. Вывод — добавить и вычесть f̃(x), применить треугольное неравенство. Нормы и ρ должны быть заданы и вычислены с гарантией не занижения. Для разных родителей используется согласованная product-норма; для сложения двух аргументов в max-норме L=2. Если условия неизвестны, NO_BOUND. Допуск `|a-b|≤ε` нетранзитивен: 0≈0.75 и 0.75≈1.5 при ε=1, но 0 не близок к 1.5. Компилятор обязан учитывать композицию допусков.

## 4. Обучение и операторы

Для MSE `L=(1/m)Σ(a-y)^2`, `δ_out=2(a-y)⊙φ'(z)/m`; в DAG `δ_v=φ'_v⊙Σ_{c child v} W_{c,[v]}ᵀδ_c`. Суммируются все uses общих параметров. Для `C=AB`: dA=dC Bᵀ, dB=Aᵀ dC. При ReLU(0), rounding и квантовании настоящий градиент либо не определён, либо не равен STE. Surrogate обозначается отдельно. Для frozen параметра обновление ноль, но полная производная по формально свободному параметру может быть ненулевой.

Градиенты и optimizer-state кандидата получают из одного snapshot; публикация в согласованной точке атомарна или операция возвращает указанный отказ. Для plain SGD, если ∇L является Lg-Lipschitz на области обеих траекторий, шаги одинаковы и ошибки градиента ограничены δg, `e_{t+1}≤(1+ηLg)e_t+ηδg+ρ`. Это следует из треугольного неравенства. Не доказывает сходимость и не переносится автоматически на quantized projection и другие optimizer.

Cross entropy при конечных logits, k=argmax, m=z_k: `CE=(m-z_t)+log1p(Σ_{j≠k}exp(z_j-m))`. Это вещественное тождество. Реализация нуждается в отдельном error contract для exp/log1p, переполнения разности, underflow и исключений. LayerNorm: `μ=Σx/n`, `v=Σ(x-μ)^2/n`, `y_i=γ_i(x_i-μ)/sqrt(v+ε)+β_i`, n>0, ε>0. Масштабирование само по себе не доказывает устойчивости при близких входах. Для attention softmax по непустому разрешённому множеству веса неотрицательны и суммируются в 1; каждая координата результата лежит между min и max значений. Равенство online/full в R следует индукцией по паре нормированных сумм, но не доказывает безопасность FP-сумматора.

## 5. Отдельные нейронные помощники

`h_i^{φ_i}(Encode_i(task,S_snapshot,evidence),rng_i)→Proposal_i | ABSTAIN`, где φ_i — собственные веса малой модели и не входят в Θ целевой сети. Каждый helper объявляет поддерживаемые формы, входной encoder, выходной язык предложений, допустимые изменения, ресурсы, режим randomness и версию. Независимый validator по фактическим байтам проверяет task binding, base revision, допустимые изменения, формы, численный профиль и конкретную battery. Конфликтующие предложения сравниваются по заранее заданным метрикам, либо отклоняются; объединение без проверки запрещено. Нет допустимого предложения — ABSTAIN/NO_HELPER.

Теорема stale rejection: если base и current сравниваются одновременно с публикацией под одним lock/CAS, ν строго возрастает без повторов и proposal связан с base, то proposal из прежней версии не публикуется после нового commit. Изоляция snapshot и запрет записи обязательны как реальные свойства исполнения. Хэш основывается на предположении collision resistance; не доказывает истинность evidence. Безопасность в этой модели не доказывает качество или независимость ошибок помощников.

Для конкретного помощника ещё нужны objective, данные и разбиения, алгоритм обучения, модель доступа к графу/весам, отдельные проверки и сравнение при общем бюджете с NO_HELPER. При конечной фиксированной батарее не следует общая корректность на всех задачах. Сумма памяти включает целевую сеть, активные отдельные φ_i, staging, scratch, verifier и runtime с учётом времени жизни. Без проверенных верхних границ это оценка, а не доказанное размещение. Длина критического пути DAG — нижняя граница времени при ограниченных исполнителях; фактическое расписание включает конкуренцию за ресурсы.
