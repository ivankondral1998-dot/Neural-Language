# NL-COMP-001 — pre-registered change-aware computation experiment

Дата: 2026-11-08. Режим: независимое исследование, НЕ изменение компилятора/языка.
Продуктовый ориентир: `NEURAL_LANGUAGE_PRODUCT_CHARTER.md`.

## Вопрос

Есть ли измеримое преимущество вычисления только затронутых состояний после пакета локальных изменений весов нейронной сети **против оптимизированного полного CPU-прохода**, а не только против старого кода Neural Language?

## Гипотеза H1, до измерений

Для сети с фиксированным входом, dense FP64, ReLU и единичными изменениями весов последнего слоя инкрементальный пересчёт должен давать выигрыш против GEMV BLAS; при большом числе изменений и/или изменениях ранних слоёв выигрыш может исчезнуть. Последнее — обязательный отрицательный случай.

Это стандартная оптимизационная идея, НЕ новое математическое открытие. Языковая новизна потенциально возможна только при выразимом/верифицируемом контракте эффектов изменений, который компилятор сможет использовать для выбора стратегии.

## Условия

- Фиксированные последовательные сети 128→256→32 и 256→512→128, FP64, ReLU hidden, linear output.
- Одинаковый случайный источник, вход, веса, позиции и значения правок для всех алгоритмов; seed=20261108.
- Батчи по 1, 8, 32, 64 весовых правки либо в первом, либо в последнем слое. Один расчёт после каждого батча. Повторы `reps=5`, `steps=250`; первые 32 шага каждой реализации — прогрев, вне замера. Порядок методов циклически меняется по повторениям.
- Методы: ручной полный C++ проход `-O3` (независимая row-major реализация), полный OpenBLAS GEMV однопоточный, изменение + инкрементальный пересчёт (rebase полным расчётом не реже 128 событий).
- В расчёт латентности входят и применение изменений весов, и вычисление выхода, и управление состоянием. Конструирование исходной сети/входа и генерация списка правок не входят (одинаково для всех).
- Корректность: траектория после каждого шага сверяется с независимым полным проходом `OpenBLAS`; относительная+абсолютная допустимая граница `1e-9 * (1+abs(y))`. Для сомнительных профилей выдавать `ERROR`, не считать скоростью.
- Формат результатов: `metadata.json`, `results.json`, `results.csv`, stdout/stderr, версии компилятора и CPU; медиана 5 повторов и p95 per-step. Порог победы для *предварительной* гипотезы: >=20% снижение медианного времени при корректном результате и повторяемости не менее 4 из 5. Целевой Android-порог НЕ установлен.

## Границы

Сравнение отдельного экспериментального вычислителя **не является измерением существующего Model::infer в нейронном runtime**, не является доказательством нового языка/новой семантики и не равняется физическим испытаниям ARM64. BLAS нужен именно как честная внешняя реализация GEMV. Нет GPU/NPU, батчевого обучения, KV-cache, sparse connectivity и смены входов. Перенос в язык возможен только после дополнительной независимой проверки на действующем runtime и мобильном устройстве.

Не проводить GitHub Actions; не сливать экспериментальную ветку в main; не удалять старые артефакты.
