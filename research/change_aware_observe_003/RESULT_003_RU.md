# NL-COMP-003 — automatic reuse for ordinary observe

Дата: 2026-11-08. Статус: ограниченный проверенный прототип Linux x86-64; Android/ARM64 и энергетическое преимущество НЕ проверены.

## Продуктовая задача

Ранее Neural Language повторно использовал нейронные состояния только при явной команде `observe_delta`. Обычная существующая команда `observe [полный вектор]` при любом изменении сбрасывала кэш. Это лишало потоковые программы возможности получать выигрыш без ручного управления изменениями.

Теперь `Model::observe()` распознаёт изменения координат, объединяет повторные изменения и применяет имеющийся частичный пересчёт, если его стоимость ниже полного прохода. Синтаксис, компилятор и Neural IR для старых `.nir` не изменены. Это известный принцип инкрементальных вычислений, **не** новый математический алгоритм.

## Проверяемые свойства

- Значение полного `observe` остаётся заменой текущего входного вектора. Инференс сопоставляется с полным прямым проходом с численной погрешностью, а не считается бит-в-бит равным в FP64.
- Повторные изменения координаты объединяются относительно значения входа, на котором был рассчитан кэш. Отменившиеся изменения не запускают пересчёт.
- Обработка полной серии входных изменений использует фиксированную 2048-байтную карту на стеке вместо квадратичного поиска.
- Если существующая эвристика уже предсказывает FULL, накопление событий прекращается заранее. Для небольших сетей (меньше 65 536 весов) неявная оптимизация `observe` отключена в AUTO: накладные расходы могут быть выше BLAS.
- **Обучение не использует приблизительные кэшированные активации:** `learn` сначала выполняет канонический полный forward. Это исправляет обнаруженный регрессионным тестом `verify weight mismatch` эффект округления, переносившийся в SGD.

## Испытания

Исходная ветка: `feature/change-aware-input-20261108`, коммит `289f4a88b9ea8fd9c347b53206e6e3cf202193ec`.
Исходный Git blob runtime: `c470b773603c4e43b3e5e3ae949781a02c099ec4`.
Новый Git blob runtime: `d6ff7aa46b6f4688422ed2df469a89033d0a9caa`.
Компилятор не изменён, Git blob `3232851491df9fc643087f7b4a054eba937789c5`.

**Регрессии:** 64/64 unittest PASS (включая старые программы, обучение, сохранение/загрузку, проверки входа/выхода, explicit/implicit delta, GCC и Clang). Стресс-тест независимого расчёта через long double: 105 300 сравнений на компилятор, максимальная нормированная ошибка ≈2.84e-15, 49 995 объединённых событий и пять отменённых пакетов.

**Производительность:** Linux x86-64, AMD EPYC 9V74, GCC/Clang, один поток OpenBLAS SciPy, `-O3 -march=native -fno-fast-math`. Сравнены реальные `Model::AUTO` и `Model::FULL` на одинаковых полных `observe`, одинаковых данных и весах, в пяти парных повторах × 256 кадров. По результатам четвёртой независимой серии (5 сетей × 5 размеров изменений):

| Критерий | GCC | Clang |
|---|---:|---:|
| Проверено сценариев | 25 | 25 |
| Сценариев с ускорением ≥20% и повторяемостью ≥4/5 | 8 | 8 |
| Медианных замедлений >20% | 0 | 0 |
| Максимальная нормированная численная ошибка | 3.86e-15 | 3.86e-15 |

**Отрицательные результаты сохранены:** первоначальная реализация замедлялась на 24–27% при плотных обновлениях; после первого исправления обнаружена регрессия на малых сетях; на третьем отложенном тесте Clang показывал до +65.5% медианного замедления. По этим результатам введён консервативный guard; прежние серии не переименованы в успех. Во время четвёртой серии конфигурация с 2240 входами была отвергнута как превышающая контракт 2048 и до допустимого запуска заменена на 2016 входов.

Полные регистрационные документы, источники, все промежуточные отрицательные измерения, CSV, журналы и SHA-256 находятся в отдельном архиве NL-COMP-003, предоставляемом владельцу. GitHub содержит исходники benchmark и тестов, что позволяет повторить проверку. Не считать отчёт доказательством общего выигрыша или новизны.

## Результат и граница

**ПРИНЯТО только как изолированный прототип:** существующие программы на самом языке теперь могут автоматически получать экономию операций на некоторых потоковых нагрузках. Выигрыш обусловлен старой известной математикой; возможность аналогичной оптимизации в обычной библиотеке не исключена.

Не объединять автоматически с `main`, `NeuralShapes/1`, `NeuralEffects/1` и DAG 0.4. Эти направления требуют самостоятельной интеграции семантики и нового набора регрессий. Следующая обязательная граница — реальные ARM64/Android измерения против актуальных оптимизированных мобильных backend (включая RAM и энергию).
