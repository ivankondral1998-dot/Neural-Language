# NL-COMP-005 — единые формы, эффекты и обновления состояния в Neural Language

Дата: 2026-11-08. Статус: **проверенная интеграция компилятора для последовательных dense-сетей**. Источник: `feature/effects-changes-integration-20261108`, HEAD при начале `57e43b9ee3690a4656f57af16ffeadc42ebe4f57`. Это не утверждение нового математического алгоритма и не Android-релиз.

## Проблема уровня языка

После NL-COMP-004 модель Neural IR уже описывала эффекты (`NeuralEffects/1`) и точечные изменения входа (`NeuralChanges/1`), но генератор нативного кода по-прежнему доверял части данных из изменённого IR: размерам слоёв, форме `observe`/`learn`/`validate`, индексам `weight`/`edge`, метаданным бюджета. Это серьёзное препятствие для будущих компиляторных преобразований и графовых вычислений. Ошибка в преобразовании IR должна обнаруживаться до генерации C++, а не становиться ошибкой выполнения.

## Реализация

Перенесён существующий принцип `NeuralShapes/1` из ветки `fix/neural-ir-shapes-20261108`, без создания нового типа компилятора. Добавлена сигнатура `observe_delta` с входным индексом и конечным `f64`-изменением.

- Парсер создаёт канонический `shape_contract`, `semantic_contract` и, при наличии `observe_delta`, `neural_changes`.
- Перед `emit(ir)` и `analyze_ir(ir)` повторно вычисляются допустимые формы, типы, диапазоны, ресурсная арифметика и семантика операций.
- Проверяются заявленные метаданные; повреждённый IR отклоняется управляемой `CompileError`.
- Старый in-memory IR без `shape_contract` допускается через повторную верификацию исходных полей; это не означает доверия непроверенным метаданным.
- Исправлен дефект: повреждённая метка `rewind` типа `list` ранее вызывала `TypeError`, теперь отклоняется `CompileError`.
- Синтаксис `.nir`, нативный runtime и сгенерированный C++ для девяти штатных примеров не менялись.

Область действия **строго** ограничена прежней сетью последовательных полносвязных слоёв, до восьми слоёв, 2048 входов и 4 млн весов. Это не общая типизация тензоров, не контракт совместимости DAG 0.4, не модель исполнения GPU/NPU и не гарантия RSS/энергопотребления.

## Следующий критерий — не ещё одна инфраструктура

На пути к мобильному преимуществу пока доказано лишь, что компилятор способен безопаснее оперировать существующей ограниченной семантикой. Следующий инженерный выбор: согласованная графовая зависимость (DAG) с доказанной корректностью/выгодой частичного вычисления **или** прямое ARM64-испытание настоящего runtime. Не принимать новый синтаксис только ради новизны. Без физического Android и оптимизированного независимого backend заявления о мобильной победе недопустимы.

По состоянию этапа `main`, экспериментальный DAG 0.4, мобильная JNI-ветка и другие проекты не изменялись. GitHub Actions не запускались.
