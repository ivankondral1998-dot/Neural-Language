# Neural Language — исправление инженерного подхода (2026-11-08)

Статус: **экспериментальная ветка**. Не изменяет утверждённую владельцем цель. Этап 0.5 не является утверждением завершённой архитектуры языка.

## Зафиксированная цель (не пересматривается агентом)

Специализированный язык программирования для разработки искусственного интеллекта, включающий управление нейронными структурами, весами и обучением; трансляцию в эффективное исполняемое представление; и **помощника, который действительно использует язык, предлагает изменения, проверяет их и не принимает ухудшения без доказательств**. Автономность выполнения без облака — желательная техническая характеристика, Android — целевая платформа исследований, но мобильная работоспособность пока не подтверждена.

Не смешивать с UNO, «Искрой», Jarvis и другими продуктами. Не обосновывать необходимость нового языка лишь тем, что мы написали новый синтаксис.

## Новая неизменная процедура для каждой функции

1. Сначала актуальная ветка и commit SHA, `AGENTS.md`, контрольные хеши изменяемых файлов, существующие тесты.
2. Каждая работа должна закрывать конкретный пробел первоначальной цели; иначе работа откладывается, а не получает статус приоритета.
3. Формулировать измеримое поведение и **отрицательные критерии** до реализации. Сначала маленький воспроизводимый сценарий, затем код.
4. Переписывать только в отдельной ветке, не затрагивая `main`, не удаляя старые файлы и не используя GitHub Actions.
5. Сравнивать с разумным baseline при одинаковых условиях: входы, training schedule, ограничения, способ измерения. Отчёты качества отдельно от отчётов скорости.
6. Доказательства: native build/run, независимый численный эталон, негативные тесты, регрессия старых версий, файлы и контрольные суммы.
7. Метрики, отказ, ограничения, что не проверено — публиковать вместе с исполняемым кодом, без заявления «готовый язык/ИИ».
8. Решение изменить генеральную архитектуру или подключить UNO принимает владелец. Агент может предложить, но не подменять им утверждённую цель.

## Что значит закрытый цикл помощника 0.5

Вход: ограниченная обучающая программа `.nir` (один FP64 линейный слой) и JSON с отдельными `validation` и `test` (валидация отделена от обучения по точному совпадению входов).

- Compiler parses `.nir` -> Neural IR; assistant **строит кандидат DAG** (линейная ветвь + ReLU-ветвь), сохраняя train-операции, seed и budget; сериализует обратно в `.nir`.
- Compiler generates C++17; обе программы собираются и исполняются изолированно в отдельных файлах, с одинаковыми примерами и графиком обучения.
- Native runtime сохраняет веса и выдаёт предсказания; отдельный Python-эталон читает `NLMODEL2/3` и независимо считает прямой проход.
- По ошибке validation и заданному порогу принимается ACCEPT или REJECT. **Метки test не участвуют в решении**: test сообщает постфактум, насколько оно оказалось удачным.
- Непринятый кандидат не публикуется как `recommended.nir`, исходная программа никогда не перезаписывается. Результаты каждого запуска и хеши исходных файлов записываются в `evidence.json`.

Это **не** нейросетевой агент и не универсальный поиск архитектуры; один фиксированный вариант. Он не улучшает веса существующей обученной сети, а обучает другой вариант с нуля. «Откат» означает непубликацию кандидата; живое состояние модели на исходном устройстве не менялось.

## Важные незакрытые пункты

- Язык пока не универсален: Neural IR JSON не является полноценной типизированной тензорной IR; оптимизация графа/динамическая перестройка в runtime отсутствуют.
- `reference_eval.py` сверяет **только forward** по сохранённым обученным весам. Это не независимое доказательство формулы всех градиентов (для конкретного DAG есть отдельный `graph_gradient_oracle.cpp`).
- Эксперимент на одной нелинейной функции не доказывает обобщение, пользу собственной грамматики относительно PyTorch/Optuna/MLIR, энергосбережение, ARM64 или автономное самообучение.
- Статическое ограничение весов/MAC, timeout не являются гарантией максимальной RAM/времени/энергии Android.
- Сценарий используется только с доверенными исходными файлами; C++ исполняемый файл не является sandbox для недоверенного кода.
- Для дальнейших решений обязательны репрезентативные задачи, несколько seed, справедливое сравнение с существующими средствами и реальный профиль ресурсов.

### Технические ориентиры для независимого сравнения

- PyTorch FX: https://docs.pytorch.org/docs/2.15/fx.html — преобразование вычислительных графов.
- MLIR: https://mlir.llvm.org/docs/ — диалекты, типы, каноникализация, преобразование.
- Optuna: https://optuna.readthedocs.io/en/stable/reference/generated/optuna.study.Study.html — автоматизированный selection/tuning на валидации.

**Правило:** функции, уже существующие в этих инструментах, не выдавать за уникальное изобретение Neural Language.
