# NL-TRAIN-002 — непрерывные FP64-цели в Neural Language

**Барьер языка.** NL-TRAIN-001 обучает классификацию: файл данных начинается с целочисленной метки, далее входные признаки; выходной вектор one-hot создаётся в native runtime. Для регрессии, восстановления сигналов и моделей с непрерывными целями нельзя было передавать обучающий вектор из файла.

**Новая конструкция .nir:**

```nir
brain VectorRegression {
  senses 2
  neurons predictions 2 linear
  init 42
}
train_data "targets.txt" samples 4 epochs 80 rate 0.1 seed 17 targets vector
save_model "regression.nlw"
```

Файл targets.txt содержит `senses` FP64-признаков, затем по одному FP64-значению на каждый выход нейросети; никаких целочисленных меток. Существующая запись без `targets vector` остаётся классификацией и **не меняет** прежний C++-код. Для регрессии допускается один выход.

Компилятор фиксирует режим в типизированном Neural IR, проверяет число входных и выходных полей и бюджет `samples × (senses + outputs)`. После проверки всех строк native runtime обучает тот же канонический SGD и сохраняет параметры в существующем формате весов. Старая реализация классификации не меняет формат обучения и использует прежний вызов функции.

**Пример и воспроизведение:** `research/nl_train_002/run.sh`. Он компилирует две независимые программы `.nir`, обучает два выхода функции `(x0,x1) → (x0,x1)` и проверяет отложенный inference. Рабочие файлы сохраняются в выведенном `run_dir`; удаления нет.

**Фактическая проверка в текущем чате (ограниченная):** локальная сборка C++17 с моделью-заглушкой и адаптированной реализацией загрузчика на GCC и Clang прошла регрессию двух непрерывных целей, максимальное отклонение 0.00132116 на четырёх примерах; некорректная FP64-цель отвергнута. Дополнительно валидный классификационный и регрессионный ввод, а также отказ на NaN прошли ASan+UBSan в GCC и Clang (LeakSanitizer не использовался). Это не проверка всего Neural Language: настоящие compiler.py/runtime и все unittest в текущем контейнере недоступны.

**До приёмки:** прогнать `python3 -m unittest discover -s language/tests -v` из корня данной ветки, `sh research/nl_train_002/run.sh`, затем GCC и Clang и, при необходимости, Android/ARM64. Функциональность не считать интегрированной в main, пока реальные .nir программы не прошли.
