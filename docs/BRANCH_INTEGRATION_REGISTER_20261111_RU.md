# Neural Language — реестр веток и интеграции в main

Дата сверки: **2026-11-11**. Режим: инвентаризация существующего GitHub, без удаления веток и без запуска GitHub Actions.
Исходный `main`: **1168f3fcc2ecd0bd17de08be69d313844790c845**.
Основание: GitHub branch list/tree/compare, исходные отчёты и независимый аудит NL-MATH-001–006 от 11.11.2026.

## Решение по main

**Main не пустая:** в ней Neural Language 0.3, `.nir`→Neural IR→C++17, runtime, FP64/INT8 хранение, `run.sh`, независимый узкий oracle и тесты. Это **принятая существующая база 0.3**, но не готовый промышленный язык и не общая корректность всех программ.

**Вне main нет реализации, для которой сейчас подтверждена полная интеграционная приёмка относительно текущей main.** Исторические PASS относятся к исходным исследовательским HEAD/узким сценариям. Они не гарантируют совместимость при выборочном переносе. Поэтому не делать слепой merge крупных веток: новый код — только после проверки эквивалентности, регрессий и реального выполнения выбранных `.nir`.

**Известный дефект самой main:** алгебраический DELTA может расходиться с FULL; `learn` может менять live weights до поздней ошибки (см. независимый аудит Астры, §6). Main — сохранённая 0.3, **не объявлять её безопасной для всех режимов**.

### Что считать завершённым и пригодным к main

Для каждого небольшого изменения обязательны:
1. Понятный контракт, не подменяющий цель языка; точная база HEAD, границы изменений и возможность отката.
2. Повторение дефекта до исправления или независимый oracle; проверка edge cases, отказов и сохранности состояния.
3. Регрессии `language/tests`, `run.sh`, сравнение legacy `.nir`, проверка GCC/Clang там, где меняются нативные вычисления. Не объявлять PASS по одному историческому логу.
4. Точная проверка после *применения к main*, а не только в исходной ветке. При изменении численного профиля — эквивалентность с заданным эталоном; ошибки не скрывать допуском.
5. Переход в main только при выполнении конкретных критериев; эксперименты и отрицательные результаты остаются в своих ветках. Скорость Android — отдельная проверка, не обязательна для слияния чисто компиляторной safety-правки, если заявляется только её узкое свойство.

## Порядок интеграции (без автоматического слияния)

**P0 — численная безопасность.** Изолировать проверенные куски из `fix/strict-numeric-independent-20261110` и `fix/canonical-delta-contract-20261110`, сверить с дефектами FULL/AUTO/DELTA, rejection semantics и staged SGD. Обязательны тесты stale cache, rounded cancellation, исключение на позднем градиенте, отказ без частичного обновления. Сначала минимальный patch в отдельной интеграционной ветке, затем тесты и только после них main.

**P1 — типизированный IR.** `fix/neural-ir-effects-20261108`, `fix/neural-ir-shapes-20261108`, `feature/typed-changes-effects-20261108`. Исторически заявлены 107 завершённых тестов и byte-identical output для 7 старых `.nir` на ветке shapes; это сильный **кандидат**, но в GitHub присутствуют манифесты, не все исходные логи. Нужно пересобрать на актуальной базе. При переносе следует отделить statically verified shapes/effects от расширения DAG и runtime.

**P2 — DAG и инкрементальные вычисления.** `feature/dag-change-aware-20261109` + исправления из P0. Linux-проверки DAG и градиентов есть; сквозная корректность при всех эффектах, бюджетах и mobile-профилях не принята. Не переносить старый приближённый DELTA как strict.

**P3 — реальные языковые функции обучения.** `feature/nl-train-001-har-20261110` и `feature/nl-train-002-regression-20261110`: второй этап сообщает о проверке loader со stub, но не завершённой регрессии настоящего compiler/runtime. Отдельная приёмка `.nir` обучения/сохранения/загрузки.

**P4 — мобильные оптимизации.** `opt/nl-mobile-opt-001-20261110`, `opt/nl-mobile-opt-002-reuse-input-20261110`, `research/mobile-text-kernels-20261110` и ARM64-направления. Измерения владельца A52: CartPole after 8.039 мкс против before 8.022 мкс и C++ 7.104 мкс (новый путь не выиграл); два синтетических INT8-теста mobile 4.638/29.293 мкс против конкретного C++ 5.024/34.730 мкс. Это разнородные ограниченные нагрузки; промышленное преимущество и универсальная польза не доказаны. `opt/nl-mobile-opt-002` не прошёл заявленную независимую приёмку на устройстве. Не сливать экспериментальные backend флаги в базовый язык без равной семантики.

**Исследования отдельно.** NL-MATH-001–006 и аудит Астры: 16 замечаний (E01–E16), включая ошибки в независимых численных эталонах, схемах типов, состоянии обучения и нейронных помощниках. Архивы сохранены в `research/nl-math-preservation-20261111`; не являются утверждённой спецификацией. У помощников с собственными малыми весами есть архитектура read-only proposals/independent verifier/ABSTAIN, но нет законченного контракта конкретной обучаемой модели. Их разработка не подменяет язык.

## Текущее решение

- В `main` переносится этот **реестр статуса** (документация, не исполняемый код).
- **Кодовые merge: 0**, потому что нет актуальной полной приёмки перенесённого изменения на базе main.
- Не удалять и не переписывать архивные ветки; не открывать массовые PR и не запускать Actions.
- Начать с P0, прежде чем расширять функциональность языка. Цель — законченный и проверяемый `.nir`, а не число веток или модулей.
