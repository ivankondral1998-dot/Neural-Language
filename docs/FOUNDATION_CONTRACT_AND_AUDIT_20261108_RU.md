# Neural Language — ревизия инженерного фундамента, 08.11.2026

**Назначение документа:** зафиксировать проверенное состояние, реальные дефекты и границы разработки. Это **не** новое техническое задание владельцу и **не** утверждение конечной архитектуры. Главная цель владельца уже задана: новый специализированный язык программирования для создания, обучения и исполнения ИИ. Вспомогательные программы с отдельными весами могут исследоваться, но не превращаются автоматически в часть языка.

## 2. Что в действительности является языком

| Компонент | Что реально имеется | Статус |
|---|---|---|
| Исходный `.nir` | Специальная грамматика: `brain`, входы/слои, команды обработки, обучения, локального изменения весов/масок, `cycle`, проверки и снимки | РЕАЛИЗОВАНО, узкая область |
| `compiler.py` | Python bootstrap: синтаксический разбор, формы, ограничение размера, генерация JSON и C++17 | РЕАЛИЗОВАНО |
| Neural IR JSON | Сериализованное дерево описания сети и команд с размерами и оценкой ресурсов | РЕАЛИЗОВАНО; **не** независимая типизированная тензорная IR с проходами оптимизации |
| Генерация | Шаблонный C++17 и сборка GCC/Clang | РЕАЛИЗОВАНО; нет самостоятельного машинного backend |
| Нейронный runtime | C++17: прямой проход, SGD, маски, снимки, сохранение весов, частичный пересчёт в некоторых сценариях | РЕАЛИЗОВАНО, ограниченная область |
| `advise` / `optimize` | Выбор между существующими режимами вычислений по синтетическому профилю | ВСТРОЕННАЯ ЭВРИСТИКА, **не** интеллектуальный разработчик языка |
| `assistant.py` версии 0.5 | Отдельная Python-программа для одной предусмотренной архитектурной перестройки | ВНЕ ЯДРА ЯЗЫКА, необязательный эксперимент |
| Десять процессов и общие веса | Внешняя оркестрация сохранения/обновления весов | ВНЕ ЯЗЫКА, не доказательство параллельного интеллектуального анализа кода |

C++ как язык реализации runtime **не отменяет** возможность существования собственного языка `.nir`. Но сами оптимизации C++-библиотеки не доказывают уникальность `.nir` и не должны рекламироваться как его преимущество.

## 3. Обнаруженные ошибки и решения

| ID | Установленный факт | Инженерное действие | Итог |
|---|---|---|---|
| F-01 — подмена продукта | Действующий `AGENTS.md` называл внешнего помощника обязательной частью утверждённой цели, а недавние ответы принимали побочные эксперименты за основную работу | Исправить действующие инструкции; основной продукт — язык и его компиляция/исполнение. Эксперименты остаются отдельными | ИСПРАВЛЕНО в ревизионной ветке |
| F-02 — неявная подмена `init` | Два объявления `init` в `brain` ранее принимались: последнее значение без предупреждения меняло seed | Запретить повторный `init`; сохранить отсутствие `init` (seed=11) и один `init` без изменений | ИСПРАВЛЕНО; новые регрессионные тесты |
| F-03 — невалидные программы | Код без `observe` перед `predict` и `learn` проходит компилятор, затем отвергается в C++ runtime | Зафиксировать несовпадение статической и динамической проверки; не менять существующую семантику без отдельного контракта и миграции тестов | ОТКРЫТО; намеренно не менялось |
| F-04 — неопределённость Neural IR | JSON сейчас содержит структурированное описание, но нет отдельной типизированной IR, нормативной семантики всех операций и собственного оптимизационного pipeline | Не объявлять JSON полноценной MLIR-подобной IR; типы/состояния/эффекты определить до расширения синтаксиса | ОТКРЫТО |
| F-05 — неверные критерии прогресса | Ранние ускорения 0.2 сравнивались в том числе со слабым старым режимом, а не с оптимизированными независимыми backend | Разделить скорость runtime, корректность языка и качество обучения; не утверждать преимуществ без честного baseline | КОРРЕКТИРОВКА ОЦЕНКИ; новый бенчмарк не запускался |
| F-06 — неоправданные заявления | `budget` — оценка основных тензоров/MAC, INT8 SGD теряет мелкие шаги, Android не испытан | Ограничения оставить явными; не трактовать estimates как RAM guarantee | ОТКРЫТО, не выдавать за реализованное |
| F-07 — несогласованная эволюция | 0.4 и 0.5 не являются основной проверенной версией; функции DAG и внешнего помощника не представляют единый утверждённый интерфейс | Не сливать ветки автоматически и не объявлять их новой обязательной архитектурой | Зафиксировано |

## 4. Зафиксированное поведение базового языка 0.3

- Программа начинается с **одного** `brain`; внутри задаются `senses`, последовательные слои `neurons`, опциональные `init`, `budget`; исполнение задаётся ограниченным набором команд. Это не общий язык с определениями пользовательских функций и типизированными тензорами.
- В базовой реализации допускается до восьми слоёв, не более 4 млн объявленных весов. Ресурсные лимиты не являются верхней границей RAM ОС.
- Один `init` задаёт воспроизводимую инициализацию; если он отсутствует — исходное значение `11`; повторный `init` теперь является ошибкой компиляции.
- Контракт загрузки весов требует соответствия формы/структуры сохранённой модели. Источник `.nlw` должен быть доверенным; отсутствие файлового доступа вне текущего каталога не является изоляцией ОС.
- Кодогенерация остаётся `.nir → Neural IR JSON + C++17 → native binary`. Python выполняет компиляцию, **не** исполняет скомпилированную программу.
- `validate` не обеспечивает автоматическую независимость тестовых данных от обучающих. `verify` сверяет пути одной реализации, а не независимую математику.
- Для некоторых команд обязательный вход обеспечивается проверкой **во время выполнения**; это недостаток статической диагностики, а не доказательство неправильной математики runtime.

## 6. Неизменные критерии следующей инженерной работы

1. Каждый новый оператор должен закрывать конкретную невозможность выразить нужную нейронную программу **на самом языке**, а не дублировать существующую команду C++ runtime ради версии.
2. Сначала описать входы, выходы, формы, состояние, последствия и ошибки оператора; затем зафиксировать минимум один положительный, один отрицательный и один эталонный тест; только потом реализация.
3. Изменения runtime сравнивать с независимым вычислительным эталоном. Изменения компилятора — с проверкой generated IR/native и совместимости ранее принятых `.nir`.
4. Каждый эксперимент может быть полезным, но он не становится обязательной частью продукта без доказательства пользы именно языку и решения владельца при изменении архитектуры.
5. Не запускать GitHub Actions, не трогать UNO, не удалять старые версии и не заявлять о прохождении непроведённых проверок.

**Ближайшая техническая граница:** согласованный контракт исходных конструкций `.nir` и Neural IR со статической проверкой форм, обязательных состояний (`observe` перед использованием) и эффектов (`learn`, `rewind`, `save_model`) — на основе имеющейся реализации, а не нового экспериментального помощника. Это **рекомендуемое инженерное направление**, не новая утверждённая владельцем цель.
