# Neural Language — проверка обязательного входного состояния

**Дата:** 08.11.2026. **Статус:** проверенное узкое исправление компилятора, не новая версия ядра и не утверждение всего языка.

## Дефект и точный контракт

До исправления корректная синтаксически программа `brain ... }\npredict` могла пройти компилятор, но падала в C++ runtime с сообщением `observe before ...`. Исправленный компилятор анализирует *операции уже разобранного Neural IR* до генерации C++ и отвергает использование входа до успешного `observe`.

Состояние `input_bound` первоначально `false`. Команда `observe [..]` делает его `true`. Команды `predict`, `learn`, `expect`, `verify`, `advise`, `optimize` требуют `input_bound=true`, иначе выдаётся `CompileError` с исходным номером строки.

`remember label` сохраняет признак `input_bound`, `rewind label` восстанавливает его из существующего снимка. Если метка неизвестна, прежний runtime по-прежнему отвергнет `rewind`; компилятор консервативно не предполагает вход после такого восстановления. `load_model` загружает **веса**, не входные данные. `validate [..] target [...]` вычисляет на изолированной копии и не меняет признак входа. `weight`, `edge`, `tune`, `inspect`, `report`, `save_model` также не создают вход.

`cycle N { ... }` гарантированно имеет `N>=1`; для отсутствия входа анализируется первая итерация и переносится результат тела. Это достаточно для операции требования входа на первой итерации при текущем детерминированном языке без ветвлений, но **не** анализирует полный контракт имён снимков, повторное создание снимков в циклах, файловый ввод, успешность операций ОС и исключения во время исполнения. Проверки runtime сохранены.

## Контрпример

```nir
brain Demo {
  senses 1
  neurons out 1 linear
}
predict
```

**Раньше:** компилировалось, затем завершалось ошибкой исполнения. **Сейчас:** компилятор сообщает `line 5: predict requires observe before use (input state absent)`; генерация C++ не начинается.

Положительные сценарии: `observe` перед `predict`/`learn`, восстановление снимка с входом; `validate` и `report` без предшествующего `observe` разрешены, если далее нет операторов, требующих текущего входа.

## Совместимость

- Команды `.nir`, JSON-структура `NeuralIR/0.2`, генерация C++17 и C++ runtime **не изменены**.
- Семь прежних корректных `.nir`-примеров дают **тот же JSON IR и тот же C++ исходник байт-в-байт**; сравнение записано в `evidence/compatibility_manifest.json`.
- Один **исторический тест** `test_failure_does_not_change_original_source` мигрирован: теперь проверяет отказ компилятора вместо заведомой ошибки времени выполнения. Это изменение ожидаемого поведения некорректной программы, а не скрытая регрессия.
- Действие ограничено `language/compiler.py`, соответствующим тестом и новым набором проверок. Код других проектов и C++ runtime не переносился/не модифицировался.

## Проверка и границы

Изолированное отрицательное испытание до изменения — `evidence/red_tests.log`; после изменения — `tests.test_state_effects` и обновлённые регрессии. Для актуального состояния ориентироваться на логи в `evidence/`. Следующий шаг — дальнейший типизированный контракт эффектов/состояния Neural IR **после** отдельного обоснования и тестов, не создание очередного внешнего помощника.
