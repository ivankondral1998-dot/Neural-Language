# NL-COMP-007 — потоковый inference: профиль памяти

База: NL-TRAIN-001 (7784ac2b). Изолированная ветка, main не изменён.

## Барьер
Обычный predict_data удерживает в RAM все N × senses признаков. UCI HAR требует только для матрицы 2947 × 561 FP64 около 12,6 МиБ. Это не нужно для независимого inference отдельных окон.

## Изменение языка
Новая конструкция: predict_data "har_test.txt" samples 2947 stream
Она явно включает двухпроходный режим: сначала проверить все строки без выводов и мутации модели, затем читать и исполнять по одной строке. Дополнительная память для данных O(senses), а не O(N × senses). Цена — повторный разбор файла.
Режим по умолчанию НЕ изменён. Компилятор хранит в Neural IR признак stream=true, проверяет его тип и отражает двойное чтение в статическом бюджете primitive_work. Совместимость старых .nir сохраняется.
Ограничение: входной файл должен оставаться неизменным в течение двух проходов; конкурентная мутация файла не охвачена контрактом.

## Фактические локальные пробы
На Linux x86-64 был скомпилирован тот же C++ парсер с облегчённой заглушкой Model (это НЕ полная сборка Neural Language). Синтетические 2947 × 561 FP64, одинаковые входы и прогнозы. GCC и Clang: побайтное совпадение вывода. Некорректная вторая строка: ненулевой exit и ноль байт DATA_PREDICT/stdout.
При этом peak RSS, KiB: GCC 15104 (обычный) / 1920 (stream), Clang 15104 / 1920.
Полное время, с: GCC 0.31 / 0.64, Clang 0.33 / 0.58.
Таким образом, в изолированной пробе RAM снижена, но полное время ухудшилось. Ни общего ускорения, ни экономии энергии не установлено.

## Незакрытая приёмка
Полный компилятор и полный runtime из GitHub не были доступны локально для нативной сборки в этом чате. Изменения и регрессионные тесты добавлены в ветку, но полный unittest не запускался.
Нужно: python3 -m unittest discover -s language/tests -v, GCC/Clang; сравнить стандартный infer.nir и infer_stream.nir на фиксированной HAR-модели SHA-256 30d0fbf1c19b30d8e608f79f74a87461ba75d84221732c07b6caaad7bb93a331.
После этого — физические измерения A52: peak RSS, wall time и при возможности энергия. Выигрыш допустимо заявить только по реально измеренному показателю.

Это улучшение выразительности .nir для ресурсоограниченного inference, но не замена следующих работ над мобильной производительностью, компилятором, обучением и архитектурами.
