# Neural Language — помощник инженерной проверки архитектуры (0.5 research)

## Запуск на Linux с Python 3 и GCC/Clang C++17

Из корня исходников:

```bash
bash run_assistant.sh
```

Или со своими доверенными входами:

```bash
python3 language/assistant.py language/examples/assistant_hinge_baseline.nir \
  --evaluation language/examples/assistant_hinge_evaluation.json \
  --output-dir runs/my_first_experiment
```

Папка вывода должна отсутствовать, иначе инструмент **откажется перезаписывать** результаты. `--compiler clang++` допустим при наличии Clang.

Внутри находятся `baseline_source.nir`, `proposed_source.nir`, native binaries и их `.cpp`/`.nir.json`, native checkpoints `baseline.nlw`, `candidate.nlw`, журналы сборки и исполнения, `evidence.json`. При `ACCEPT` появляется дополнительный `recommended.nir`; оригинал не меняется. Статус `REJECT_NO_VALIDATION_GAIN` означает, что указанный критерий качества не выполнен; `REJECT_RESOURCE_LIMIT` — кандидат превысил указанный лимит веса/MAC или текущий статический `budget`.

## Критерии успешной *проверки*, а не «полноценного ИИ»

- Обе программы созданы из настоящей `.nir`-грамматики, прошли проверки компилятора и выполнены как native binaries.
- Обучающие входы не совпадают с validation/test; split test не входит в решение о принятии.
- Ошибка validation нового графа снижается не меньше, чем на объявленную долю, и более чем на фиксированный абсолютный порог.
- Независимый forward-reference по сохранённым весам согласуется с native-ответами; при расхождении результат не публикуется.
- Отказ от рекомендации возможен и покрыт тестами; файл оригинала сохраняется побайтно.

## Чего этот инструмент НЕ делает

Не выполняет автоматическое улучшение произвольных `.nir`, не использует LLM и не меняет живые веса исходной программы. Не содержит производственного оптимизатора DAG, датчика RAM/энергии или защиты ОС для недоверенных программ. Результат одного запуска не доказывает, что выбранная модель лучше на других распределениях или начальных состояниях.
